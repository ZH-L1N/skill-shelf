## Deviations from spec (improvements found during recon/research)

1. **Plugin scan is manifest-driven, not glob-driven.** The spec scans
   `~/.claude/plugins/cache/*/*/*/skills/*`, but the cache holds multiple
   versions of the same plugin side by side and some version dirs are content
   hashes (not sortable). The sync script instead reads
   `~/.claude/plugins/installed_plugins.json` — the authoritative manifest
   mapping each plugin to its active `installPath` (prefer the `user`-scope
   entry; fall back to any) — and scans `<installPath>/skills/*` only.
   A manifest plugin whose installPath has no `skills/` directory is skipped
   at discovery time (live cases: `code-review`, `swift-lsp`), never
   registered as a scan root.
2. **Showcase images live in `src/showcase/`, not `public/showcase/`.**
   Astro's `astro:assets` `<Image>` only optimizes imported assets; `public/`
   files ship verbatim. Cards use optimized thumbnails via `<Image>`, and the
   full-size link is a plain `<a href={img.src}>` — lightbox behavior with
   zero client JS.

Task 8 back-propagates both deviations into the spec (supersession notes) so
the two documents never disagree.

## Global constraints

- **No Exowatt/org content ever enters the repo.** Defense in depth, every
  layer implemented, tested, and continuously exercised:
  1. `BLOCKLIST` constant in `scripts/lib/inventory.mjs`: marketplace keys
     matching `/exowatt/i` (pattern, not exact string) and the personal slug
     `offline-read-telemetry-policy`. A committed unit test asserts the real
     constant's contents (deleting/typo'ing an entry fails `npm test`).
  2. Content denylist, checked over the **pre-blocklist** scan results:
     plaintext term list at `~/.config/skill-shelf/denylist.txt` — outside
     the repo entirely (no gitignore interplay, survives re-clones), path
     overridable via `SKILL_SHELF_DENYLIST`. Its loss-recovery story is an
     explicit, named mechanism set up in Task 3 — NOT an assumed backup
     (verified 2026-08-16: this machine has no Time Machine destination
     configured, so "home-dir backups" would be a false premise).
     ALL gate logic is pure and unit-tested in `scripts/lib/inventory.mjs`:
     `matchesDenylist(fields, terms)` plus
     `denylistGate({terms, preBlocklist, postBlocklist}) -> {ok, reason}`;
     `scripts/sync.mjs` only calls the gate and honors its verdict. The
     gate's checks, in order:
     - **Floor:** fewer than `DENYLIST_MIN_TERMS = 5` non-comment lines →
       refuse.
     - **Term-liveness self-test** (depends on nothing external): for each
       term, a synthetic record containing it must be flagged by
       `matchesDenylist` — catches empty/whitespace/malformed terms and
       verifies EVERY term, not one.
     - **Output gate:** a term match in POST-blocklist output → refuse to
       write.
     No committed fingerprint or hash of the term list: an unsalted digest
     of a small set of guessable product names is a confirmation oracle in
     a public repo (round-4 review demonstrated full-set recovery in <1ms).
     No reference copy exists either — the owner explicitly waived the
     loss-recovery mechanism (2026-08-16) and accepts the
     rebuild-from-memory risk; the decision is recorded in CLAUDE.md's
     gotchas so it reads as a choice, not an oversight.
     Softer signal, not a gate: when `offline-read-telemetry-policy` is
     present in the pre-blocklist scan and the denylist does NOT flag it,
     warn loudly (list likely incomplete) — a warning, not a refusal, so
     uninstalling that work skill can never brick sync.
  3. Sync is diff-gated on EVERY run: `npm run sync` is a dry-run printing
     an added/removed/changed summary plus the skip-list; `--write` applies.
     The human reviews the diff before committing, every time.
  4. Supplementary smoke, scoped to published artifacts only:
     `grep -ri exowatt data/generated.json data/overrides.yaml dist/`
     (necessary-not-sufficient; layer 2 is the real content gate).
- Pure static output. Zero client JS by default (still Astro's documented
  default); any interactive enhancement must justify itself.
- Everything committed is English. `npm run sync` runs only on Zehui's
  machine, never in CI (and cannot run there — the denylist file doesn't
  exist in CI, by design).
- **Astro 7.2.2** (current stable; strict Rust compiler is default — unclosed
  tags are build errors; `compressHTML` now defaults to `'jsx'`, so inline
  whitespace between badges must not be layout-significant).
- **Node >= 22.12.0** (Astro 7 floor). Local machine: v24.15.0. A committed
  `.node-version` file (`24`) pins CI and Cloudflare Pages alike.
- Runtime dependencies: `astro` + `yaml@2`. Nothing else. (`gray-matter` is
  unmaintained — hand-roll the ~8-line `---` frontmatter split; never import
  Astro's transitive `js-yaml`.)
- **Directory discovery must follow symlinks — and must not filter on Dirent
  type.** `~/.agents/skills/*` entries are symlinks (they report
  `isDirectory() === false`), and `fs.globSync` does not descend into
  symlinked dirs (`followSymlinks` needs Node >= 24.16.0; local is 24.15.0 —
  research §3.1). Discovery is `fs.readdirSync(root)` (plain names — no
  `withFileTypes`, so there is no Dirent to mis-filter on) + `fs.statSync`
  on the candidate `SKILL.md` as the sole inclusion test (statSync follows
  symlinks).
- **Git hygiene for the autonomous pipeline:** commits use explicit
  pathspecs — `git add -A` / `git add .` are forbidden. Before any push,
  assert `git status --short --untracked-files=all` shows nothing outside
  the file map.

## Data model (concrete)

### `data/generated.json` — machine-written

```json
{
  "generatedAt": "2026-08-16T00:00:00Z",
  "entries": [
    {
      "slug": "grilling",
      "name": "grilling",
      "description": "Grill the user relentlessly about a plan…",
      "runtimes": ["claude", "codex"],
      "origin": "personal"
    }
  ]
}
```

- `slug` = skill directory name (kebab-case), the merge key everywhere.
- `runtimes` ⊆ `["claude", "codex", "agents"]`, sorted; one entry per slug
  across runtimes.
- `origin` = `personal` | marketplace name (`claude-plugins-official`,
  `anthropic-agent-skills`, `openai-codex`).
- Entries sorted by slug; JSON pretty-printed with 2 spaces → stable diffs.
- If the same slug exists both personally and in a marketplace, `personal`
  wins (one entry, `origin: personal`, runtimes merged).
- **Cross-runtime tie-break is a fixed, declared precedence:** the ordered
  constant `SOURCE_PRECEDENCE = ["claude", "codex", "agents"]` decides whose
  frontmatter wins when the same slug exists in multiple personal roots with
  divergent content (live case: `proj-init` differs between claude and
  codex). `mergeEntries` consumes this constant, never discovery order.
- `generatedAt` is preserved from the previous file when the serialized
  entries are byte-identical (`toStableJson(entries, previousJson)`), so an
  unchanged inventory produces a byte-identical file.

### `data/overrides.yaml` — hand-written, two top-level namespaces

```yaml
skills:                           # keys annotate scanned entries by slug,
  grilling:                       # or declare manual cards with manual: true
    category: dev-workflow
    description: Short English card text (<= 140 chars, REQUIRED to render)
    notes: Personal commentary shown on the card
    status: active                # active | trying | archived; default active
    repo: https://github.com/ZH-L1N/…
    images: [grilling-1.png]      # files under src/showcase/

  grill-me:
    hidden: true                  # force-hide a personal entry

  superpowers:                    # manual aggregate card (no scanned slug)
    manual: true
    category: curated-picks
    description: The four skills I lean on daily — brainstorming,
      writing-skills, systematic-debugging, TDD.
    repo: https://github.com/obra/superpowers

projects:                         # fully manual; keys independent of slugs
  herdr:
    name: herdr
    description: Terminal multiplexer for coding agents…
    repo: https://github.com/ZH-L1N/…
    images: [herdr-1.png]
```

**Visibility rule** (single place, `src/lib/entries.mjs`): a skill entry
renders iff `!hidden && (origin === "personal" || manual)`. Project entries
always render. Project entries never mutate or remove skill entries — the
namespaces are disjoint by construction (this is what makes `herdr` safely
both a skill card and a project card).

**Key validation (committed test over the real data files):** every key in
`overrides.skills` must either match a slug in `generated.json` or carry
`manual: true`; unknown keys fail `npm test` naming the offender.
`mergeCatalog` also returns an `orphanedOverrides` array, logged at build.
(This is what catches a typo'd `hidden:` key before it republishes a skill
the user chose to hide.)

**Card copy rule:** skill frontmatter descriptions are LLM routing text
(median 236 chars, max 1077 across the real inventory) — unusable as card
copy. Every entry that renders MUST have a hand-written `description`
override of <= 140 chars. Runtime behavior is graceful, data is strict:
`mergeCatalog` truncates an over-cap description at a word boundary and
emits a build warning naming the slug (a routine `npm run sync` after
installing a new personal skill never breaks the build); a committed test
over the REAL `data/overrides.yaml` + `data/generated.json` asserts every
visible entry has a <= 140-char override, so a genuine gap fails `npm test`
instead.

Entries missing `category` fall into an "Uncategorized" group at the end —
visible during dev so gaps are obvious, and the initial overrides file ships
with every visible entry categorized.

### Build-time loading (per research)

No Content Layer collections: two data files merging into one card list is
a plain-code problem. The index page frontmatter does
`import generated from '../../data/generated.json'`, reads
`data/overrides.yaml` with `node:fs` + `yaml`, and calls one pure
`mergeCatalog(generated, overrides)` from `src/lib/entries.mjs` that returns
`{ skillsByCategory, projects, orphanedOverrides }`.

### Task 2 — Sync inventory logic (TDD)
`scripts/lib/inventory.mjs` pure functions, unit-tested first with built-in
`node:test` (`tests/inventory.test.mjs`):

- `parseSkillMd(text) -> {name, description}` — hand-rolled `---` frontmatter
  split + `yaml` parse; tolerate quoted/unquoted/multiline/Chinese
  descriptions; frontmatter present but missing fields → fall back to
  directory name, empty description.
- `discoverSources(homedir, manifest)` — returns scan roots: the three
  personal dirs + one `skills/` root per manifest plugin (user-scope entry
  preferred) **that actually has a `skills/` directory** (plugins without
  one are skipped at discovery, never registered as roots), each tagged
  with origin and runtime.
- Directory discovery: `readdirSync(root)` (plain names). A candidate is
  included iff `statSync(<dir>/SKILL.md)` succeeds — the sole inclusion
  test; statSync follows symlinks. **Dirent type must never be used to
  filter candidates** (symlinked skill dirs report `isDirectory() ===
  false`; that mis-filter is exactly the bug this design exists to avoid).
  Anything without a readable SKILL.md is skipped AND counted.
- `applyBlocklist(entries, blocklist)` — drops blocked marketplaces
  (pattern match) and slugs.
- `matchesDenylist(fields, terms)` — pure, case-insensitive.
- `denylistGate({terms, preBlocklist, postBlocklist}) -> {ok, reason}` —
  pure; the floor, term-liveness self-test, and post-blocklist output gate
  all live here (the CLI only honors the verdict), plus the non-fatal
  `offline-read-telemetry-policy`-unflagged warning signal.
- `mergeEntries(rawEntries)` — dedup by slug: union runtimes (sorted),
  `personal` origin wins over marketplace; within personal,
  `SOURCE_PRECEDENCE = ["claude", "codex", "agents"]` decides whose
  name/description wins.
- `toStableJson(entries, previousJson)` — sort by slug, fixed key order,
  2-space indent; preserves previous `generatedAt` when entries are
  byte-identical.

Pinned test cases (each one is a review-visible commitment):
1. cross-runtime merge unions runtimes
2. same slug, divergent claude/codex descriptions → claude text wins,
   runtimes `["claude","codex"]`
3. blocklist drops a matching marketplace AND a matching slug
4. **the real `BLOCKLIST` constant** contains `offline-read-telemetry-policy`
   and its marketplace matcher rejects `exowatt-common`
5. personal-beats-marketplace on slug collision
6. hash-version manifest path resolves via installPath
7. frontmatter present but fieldless → directory-name fallback
8. **symlinked skill directory is discovered** — fixture is a symlink
   *pointing at a directory* that contains a SKILL.md (matching the real
   `~/.agents` shape; a symlink-to-file fixture would pass while reality
   fails)
9. directory with no SKILL.md is skipped, not fatal; unreadable SKILL.md is
   skipped, not fatal
10. stable output ordering; unchanged entries preserve `generatedAt`
11. `matchesDenylist` flags a synthetic term in any field; misses when absent
12. a manifest plugin whose installPath has no `skills/` directory is
    skipped, not registered as a zero-yield root
13. `denylistGate`: under-floor term count refuses
14. `denylistGate`: a dead term (fails the liveness self-test) refuses
15. `denylistGate`: a post-blocklist output match refuses
16. `denylistGate`: a healthy list with clean output passes
17. `toStableJson` with `--out` semantics: previous state comes from
    `data/generated.json` even when writing elsewhere (see Task 3)
18. reconciliation: a merge that drops or invents a slug fails the slug
    set-equality check with the offenders named; a broken runtime union
    fails runtime conservation
19. `denylistGate` non-blocking warning pinned: returns `ok: true` WITH a
    warning when `offline-read-telemetry-policy` is present in
    `preBlocklist` and no term flags it; returns `ok: true` with NO warning
    when that slug is absent from `preBlocklist` entirely (uninstalling the
    work skill can never brick sync)

### Task 3 — Sync CLI + first real inventory
`scripts/sync.mjs` wires the pure functions to the real filesystem
(`readdirSync`/`statSync`, `os.homedir()`). Behavior:

- Default run = dry-run: prints the added/removed/changed diff summary vs
  the current `data/generated.json`, the "skipped N directories without
  SKILL.md" list, and the count reconciliation (see Verification); writes
  nothing.
- `--write` applies; `--out <path>` changes ONLY the write target.
  **Previous-state for `generatedAt` preservation is always read from
  `data/generated.json`, never from the `--out` path** (pinned test #17) —
  so the stability check compares identical timestamps by construction.
- Denylist gate: load `~/.config/skill-shelf/denylist.txt` (or
  `SKILL_SHELF_DENYLIST`), call `denylistGate(...)`, honor its verdict
  (floor → term-liveness → post-blocklist output gate; the
  unflagged-work-skill warning is printed but never blocks). Sync also
  maintains `~/.config/skill-shelf/.last-sync` (local, uncommitted —
  holding `sha256(sorted(lowercased terms))`, which detects every change
  including same-count edits and creates no committed oracle) and prints
  "term list changed since last sync — update the reference copy in
  <mechanism>" when it differs. `.last-sync` is written ONLY on `--write`,
  never on a dry-run, so the reminder persists until the change is applied.
- Fail-loud source assertion, evaluated on RAW pre-blocklist discovery
  counts (so blocklisting a marketplace to zero is never an error): every
  registered root must yield >= 1 raw entry; exit non-zero naming any root
  that produced none. Expected raw counts, measured 2026-08-16: claude 18,
  codex 21, agents 3, superpowers 14, document-skills 17, codex-plugin 3,
  plus the two org-marketplace plugins (8 skills total — their names and
  per-plugin counts stay out of committed files; the committed
  `EXPECTED_RAW_COUNTS` constant carries only personal and
  public-marketplace roots, since blocked-origin counts can never matter
  to the published output).

Create `~/.config/skill-shelf/denylist.txt` locally (never committed; its
existence and path documented in CLAUDE.md, its terms nowhere in the repo).
**Loss-recovery: waived by owner decision (2026-08-16).** Zehui explicitly
chose NOT to keep a reference copy anywhere — the denylist is
machine-local by design and he accepts the rebuild-from-memory risk.
CLAUDE.md's gotchas record this decision (so nobody later mistakes the
absence for an oversight) alongside the standing rules: the terms must
never be committed anywhere, and `~/.config/skill-shelf/` must never come
under version control.
Run sync, **manually review every entry of the diff before `--write` and
before committing** (the diff gate applies to every future sync too).
Commit data with explicit pathspecs.
